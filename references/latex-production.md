# LaTeX production

- `md_to_latex.py` converts the **approved snapshot** with pandoc using `templates/latex/<article|book>.yaml` (document class, geometry, natbib options). It refuses if approval is missing/stale or the snapshot was altered. Output: `latex/<id>.tex`, `latex/references.bib`, copied figures.
- Institutional template: set `template:` in `project-config.yaml` (a pandoc LaTeX template) or pass `--template-file`. If the institution supplies a `.cls`, ask the user how to integrate before proceeding.
- Allowed mechanical changes (always logged): drop trailing empty References heading; `[Figure](#fig-x)` → `Figure~\ref{fig-x}`. Everything else is content and must not change.
- Bibliography: natbib + BibTeX for `numeric`, `author-year` and `ieee`. Tectonic does not run biber, so biblatex is not supported. For `apa7`, `harvard`, `mla9`, `chicago-author-date`, `chicago-notes`, `vancouver` pandoc `--citeproc` builds the references with a vendored CSL file (`templates/csl/`, hash recorded in state). CSL is rejected for `ieee-report` and for custom templates that lack `$csl-refs$`. MLA narrative cites need a locator.
- Options: `scripts/layout.py` is the single place that merges built-in defaults < doctype < project config into pandoc arguments. Layout values are whitelisted (`ms_state.py layouts`); `ms_state.py check-config <id>` reports all errors at once, and `md_to_latex.py`/`validate_markdown.py` enforce the same checks. A custom `template:` or venue template honours only the layout keys it declares in `layout_options`. Generated `pandoc-defaults.yaml`, `layout-header.tex` and the CSL file are hashed into state; `verify` reports `latex_input_changed`.
- Raw LaTeX in the Markdown is not passed to the `.tex` (it can read files or run macros). Use Markdown, `$math$` and the config options.
- Venue templates (`acm-paper`, `llncs-paper`, `elsevier-paper`, `revtex-paper`, `preprint`, `ieee-report`) are pandoc templates in `templates/latex/` with front matter documented at the top of each file. Tables in two-column/venue types use the `ieee-tables.lua` filter. Springer Nature and NeurIPS/ICML/ICLR styles are not in tectonic's bundle and are unsupported.
- `thesis-formal`: opt-in front/back matter. Report YAML: title, subtitle, author, date, abstract, keywords, acknowledgements, dedication, declaration, copyright, `abbreviations`/`symbols: [{term, meaning}]`. Config `frontmatter:` (report overrides): institution, faculty, department, degree, date, supervisor, logo, declaration/copyright (`true` for standard text or your own), dedication, acknowledgements, toc, lof, lot, roman_front_matter. After setting `logo` (a file inside the project folder; paths outside it, or symlinks leaving it, are rejected) run `ms_state.py lock-logo`; the logo is hash-locked like a figure. Mark appendices `# Title {.appendix}`; they must come last and print after the bibliography as Appendix A, B. Missing front-matter fields are warnings; config text is always literal, never raw LaTeX.
- Word: see "Word output" in SKILL.md. `md_to_docx.py` uses the same layout and CSL choices where Word can express them and prints what it ignores.
- `validate_latex.py` before compiling: figure files, labels/refs, cite keys, bibliography file, environments, braces, placeholders.
- `compile_latex.sh` picks latexmk → tectonic → xelatex → pdflatex → lualatex (first available) and writes `.ms/logs/compile.log`. Report actionable errors from the log. Fix via markup/template; do not edit approved wording. If the fix requires a content change: return to Markdown and re-approve.
- The `.tex` is editable by the user, but the Markdown remains authoritative; hand edits to `.tex` are lost on regeneration — say so.
